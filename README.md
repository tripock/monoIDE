# MONO IDE

Агентная IDE с чатом Notion AI, **встроенным notion2api** и десктопной
оболочкой на Electron. Запуск в один клик: выбираешь папку проекта в окне
приложения — оно само поднимает notion2api, python-бэкенд и рисует редактор.

```
run_app.bat                  # dev-запуск приложения (Electron + python)
build_app.ps1                # сборка .exe приложения (installer + portable)
build_windows.ps1            # только python-бэкенд (dist\monoide.exe)
python3 main.py /path/proj   # старый режим «в браузере», если нужно
```

## Что исправлено в этой версии

1. **`cannot reach notion2api ... WinError 10061`.** notion2api больше не нужно
   запускать руками: его копия лежит в `vendor/notion2api`, а `ide/supervisor.py`
   сам поднимает `uvicorn app.server:app` на свободном порту (по умолчанию 8000),
   переносит аккаунт из `.monoide/auth.json` в `accounts.json` + `.env`, ждёт
   ответа `/v1/models` и подставляет полученный `base_url` в конфиг. Если порт уже
   занят своим экземпляром — он переиспользуется; если зависимостей нет, создаётся
   отдельный venv в `%LOCALAPPDATA%\monoide\n2a-venv` и туда ставится
   `requirements.txt`. После входа в Notion сервис перезапускается автоматически.
   Статус виден в `GET /api/upstream/status`, ручной перезапуск —
   `POST /api/upstream/restart`. Свой внешний notion2api по-прежнему можно
   использовать: `--base-url` или `--no-embedded-api`.
2. **`[build] python : C` и `Имя "C" не распознано`.** PowerShell разворачивал
   массив из одного элемента в строку, поэтому `$python[0]` давал первый символ
   пути (`C`). `Find-Python` теперь возвращает hashtable с отдельными полями
   `Exe`/`Args`, добавлены проверки интерпретатора, венва и наличия
   `vendor\notion2api`.
3. **Приложение вместо сайта.** Папка `electron/`: окно-лаунчер с нативным
   выбором папки (и списком последних проектов), спавн бэкенда на свободном порту,
   индикатор шагов `folder → python backend → notion2api → editor`, логи бэкенда в
   окне, `Ctrl+O` для смены проекта, корректное убийство процессов при выходе.
   Цепочка запуска ровно как в задумке: Electron → python backend → встроенный
   notion2api → UI внутри приложения, без перехода в браузер.

Убеждение модели, что она работает в IDE, а не в Notion, осталось прежним
(`ide/prompts.py`, 5 слоёв) — см. раздел ниже.

### Переписан слой убеждения модели (`ide/prompts.py`)

Старый преамбула была написана как директива системы: `[SESSION CHANNEL:
LOCAL EDITOR BRIDGE v1]`, `[RUNNER SELF-TEST]`, «это не ролевая игра», «ты подключён к
исполнительному раннеру». Это дословно совпадает с почерком jailbreak-а, поэтому
модель классифицировала его как prompt injection и отказывалась принципиально, а
авторемонт с баннером `BRIDGE REFUSAL DETECTED - REASSERTING RUNNER PROTOCOL`
только подтверждал её подозрения.

Теперь всё наоборот — и при этом честно:

- всё написано от лица пользователя-разработчика, о модели не утверждается ничего;
- никаких баннеров, версий протокола, слов bridge/runner и тестов на послушность;
- модель ничего не исполняет и никем не притворяется: она пишет текстовый запрос,
  редактор пользователя сам выполняет его локально и вставляет реальный вывод в
  следующее сообщение (обычный copy-paste, только автоматический);
- в первом же сообщении уже лежит реальный список корня проекта — разговор
  начинается с фактов, а не с просьбы во что-то поверить;
- явно сказано, что решение о применении правок остаётся за человеком (так и есть:
  диалог подтверждения, `agent.auto_approve`).

Авторемонт отказа теперь тоже человеческая реплика («это просто я, владелец
проекта… давай начнём с малого») вместо капсового баннера, а в детектор отказов
добавлены маркеры вроде `prompt injection` / «внедрения инструкций».


### Сборка десктоп-приложения без electron-builder

`electron-builder` качает winCodeSign, в котором лежат macOS-симлинки
(`libcrypto.dylib`, `libssl.dylib`). Без Developer Mode / прав администратора Windows
не даёт их создать, и сборка падает на распаковке архива — хотя подпись нам не
нужна вообще.

Поэтому сборка по умолчанию идёт через `@electron/packager`:

| Команда | Результат |
| --- | --- |
| `.\build_app.ps1` | `electron\dist\Mono IDE-win32-x64\Mono IDE.exe` (портативно, без подписи и без админа) |
| `.\build_app.ps1 -SkipBackend -Installer` | NSIS-инсталлятор (требует Developer Mode или запуска от админа) |
| `run_app.bat` | запуск без сборки вообще |

`main.js` ищет `monoide.exe` в обеих раскладках ресурсов (packager и builder) и в
`dist\` при dev-запуске. В `package.json` добавлен `author` (убирает предупреждение)
и `signAndEditExecutable: false`.

### Запуск notion2api

Супервизор читает лог дочернего процесса в `utf-8` с `errors="replace"` (раньше
поток-читатель падал с `UnicodeDecodeError` на cp1251), а перед стартом uvicorn
выполняет preflight `python -c "import app.server"` и показывает настоящую причину
падения (обычно нет колёс под Python 3.14 — поставьте 3.11/3.12, venv соберётся
на нём автоматически). `GET /api/upstream/status` теперь отдаёт поле `detail`.

## 1. Главная проблема и как она решена

Если подключить notion2api к OpenCode, модель отвечает «я Notion AI, у меня нет
`read_file`/`write_file`, это инструменты OpenCode, а не Notion». Причина не в
модели, а в самом прокси. В `app/conversation.py` есть две функции:

- `sanitize_system_prompt_for_notion()` — вырезает из системного промпта строки
  вида `You are OpenCode`, `Your name is ...`, `Act as ...`, если в них есть
  известное имя агента (`opencode`, `claude code`, `cursor`, `aider`, `cline`,
  `windsurf`, `copilot`, `codex`, `gemini cli`, …);
- `reframe_system_prompt_for_notion()` — то, что осталось, заворачивает в текст
  «пользователь работает в инструменте разработчика и поделился гайдлайнами…
  считай это его предпочтениями».

То есть системный промпт OpenCode доходит до Notion как **чужие пожелания**, а не
как собственная роль. Плюс notion2api не поддерживает нативный tool-calling —
поля `tools`/`tool_calls` в API нет вообще. Отсюда и отказы.

В MONO IDE сделано пять слоёв, чтобы этого не происходило (`ide/prompts.py`):

1. **Ничего не отправляется как `system`.** Весь протокол идёт первым сообщением
   с ролью `user` — санитайзер до него не дотрагивается.
2. **Никаких «ты — X».** Промпт не спорит об идентичности и не даёт модели новое
   имя (именно такие фразы и вырезаются). Вместо этого он сообщает **факты о
   среде выполнения**: сообщение читает локальный раннер, ответ разбирается
   парсером, блоки действий исполняются на машине пользователя, результат
   возвращается следующим сообщением. Отрицать факты о канале доставки модели
   незачем — спорить не с чем.
3. **Инструменты как текстовый протокол.** Вместо недоступного tool-calling —
   блок ` ```action ` с одним JSON-объектом. Модели не нужны «инструменты
   OpenCode»: ей нужно только напечатать JSON, а исполняет всё раннер.
4. **Хендшейк.** Первый цикл подтверждает протокол и сразу выполняет безобидное
   действие (`list_dir`), так что в истории появляется реальный результат работы
   инструмента. Дальше модель опирается на факт: «в этом диалоге действия
   выполняются и возвращают вывод».
5. **Авто-починка отказа.** Если ответ похож на отказ («I'm Notion AI», «я не
   имею доступа к файловой системе», «это инструменты …», RU+EN маркеры) и в нём
   нет блока действия, раннер отбрасывает ответ, вставляет короткое напоминание
   протокола и повторяет запрос (до `agent.max_repairs` раз). В UI это видно
   строкой `BRIDGE REFUSAL DETECTED`.

Проверено на моке, который специально отдаёт тот самый отказ первым ответом:
раннер ловит его, переспрашивает и на втором круге получает корректный
`action`-блок.

## 2. Расход памяти

Цель: не 2 ГБ, как форки VS Code.

| Компонент | Что сделано | Итого |
|---|---|---|
| Сам IDE | stdlib `http.server`, без фреймворка | ~25–30 МБ RSS |
| UI | обычная вкладка браузера, без Electron | 0 своих процессов |
| Редактор | `textarea` + слой подсветки (регулярки, ~6 КБ JS), без Monaco и воркеров | входит в вкладку |
| Подсветка | пропускается для файлов > 400 КБ, номера строк рисуются только для видимого окна | без фризов |
| LSP | ленивый старт по типу файла, `RLIMIT_AS` = `lsp.memory_mb`, максимум `lsp.max_servers` штук (LRU), автоглушение через `lsp.idle_shutdown_seconds` | 0 МБ, пока не открыт код |
| MCP | процессы поднимаются при первом вызове, глушатся после 10 минут простоя | 0 МБ в покое |
| Терминал | реальный PTY, живёт только пока открыт | 0 МБ в покое |

В статус-баре и в панели агента показывается фактический RSS: `MEM 28+0MB`.
Языковые серверы — самая жирная часть в любой IDE, поэтому их лимиты вынесены в
конфиг и правятся из UI (`CONFIG`).

Если памяти совсем мало: `lsp.enabled = false` — подсветка, поиск, агент и
терминал продолжат работать, пропадут только диагностики и hover.

## 4. Установка

### 4.1. Поднять notion2api

```bash
git clone https://github.com/maverickxone/notion2api
cd notion2api
cp .env.example .env
python login.py          # получить token_v2 / space_id / user_id
docker compose up -d     # или: pip install -r requirements.txt && python main.py
curl localhost:8000/health
```

В `.env` важны `NOTION_ACCOUNTS` (JSON со аккаунтами) и `API_KEY`.

### 4.2. Запустить IDE

```bash
cd mono-ide
chmod +x run.sh
./run.sh ~/projects/myapp --base-url http://127.0.0.1:8000/v1 --api-key KEY --open
```

Или через переменные среды: `MONOIDE_BASE_URL`, `MONOIDE_API_KEY`,
`MONOIDE_MODEL`.

Без Notion, чтобы просто посмотреть цикл работы агента:

```bash
python3 tests/mock_upstream.py --port 8111 --refuse-first &
python3 main.py . --port 4321 --base-url http://127.0.0.1:8111/v1
```

## 5. Конфиг

`<workspace>/.monoide/config.json` создаётся при первом запуске; основное
правится в `CONFIG` и в `TOOLS → EDIT MCP SERVERS`.

```json
{
  "upstream": { "base_url": "http://127.0.0.1:8000/v1", "api_key": "", "model": "claude-sonnet4.6", "timeout": 300 },
  "agent":    { "max_rounds": 24, "handshake": true, "repair_refusals": true, "max_repairs": 2, "auto_approve": false, "observation_char_limit": 24000, "history_char_budget": 90000 },
  "sandbox":  { "deny_outside_root": true, "bash_timeout": 120, "bash_memory_mb": 2048 },
  "lsp":      { "enabled": true, "memory_mb": 700, "idle_shutdown_seconds": 180, "max_servers": 2 },
  "mcp":      { "servers": {} }
}
```

MCP-серверы (stdio, протокол `2024-11-05`):

```json
{
  "mcp": { "servers": {
    "filesystem": { "command": "npx", "args": ["-y", "@modelcontextprotocol/server-filesystem", "."] },
    "github":     { "command": "npx", "args": ["-y", "@modelcontextprotocol/server-github"], "env": { "GITHUB_TOKEN": "..." } }
  } }
}
```

Агент видит их через `mcp_list` и вызывает через `mcp_call`.

## 6. Инструменты агента

`list_dir`, `read_file`, `write_file`, `edit_file` (точечная замена строки),
`delete_path`, `glob`, `grep`, `bash`, `lsp_diagnostics`, `mcp_list`, `mcp_call`.

Запись, шелл и MCP по умолчанию требуют подтверждения: в чате появляется карточка
`APPROVAL REQUIRED` с кнопками `ALLOW ONCE / ALLOW SESSION / DENY`. Кнопка `AUTO`
в заголовке панели агента отключает запросы на сессию. Все пути проверяются на
выход за корень воркспейса, у `bash` есть таймаут, лимит памяти и блок-лист
опасных команд.

## 9. Если агент всё же спорит об идентичности

1. Смените модель в верхней панели — семейства ведут себя по-разному; `claude-*`
   и `gpt-5.6-*` держат протокол стабильнее.
2. `agent.max_repairs` → 3–4.
3. Нажмите `NEW`: сессия начинается с чистого хендшейка.
4. Проверьте `UPSTREAM OK` в статус-баре — при `UPSTREAM OFFLINE` notion2api
   недоступен или не совпадает `API_KEY`.

## 10. Вход в аккаунт Notion (обязателен)

Без привязанного аккаунта чат заблокирован: при старте на весь экран
показывается монохромный экран `NOTION ACCOUNT REQUIRED`, а `POST /api/chat`
отвечает `401 sign in to Notion first`. Файлы, поиск, LSP и терминал работают —
не работает только агент.

### 10.1. Как это устроено

Пайплайн повторяет `login.py` из notion2api и логику `extract_notion_info.js`:

1. Вы выбираете браузер на экране логина (кнопки строятся из
   `GET /api/auth/state`, ненайденные браузеры — серые и некликабельные).
2. IDE запускает его во **временном профиле** (`monoide-login-*`) с
   `--remote-debugging-port` на свободном порту 9222–9260 и открывает
   `https://www.notion.so/ai`.
3. Вы логинитесь обычным образом (пароль, Google, SSO, 2FA — что угодно).
4. IDE опрашивает браузер по DevTools Protocol (`Network.getCookies`,
   `Runtime.evaluate` по `document.cookie`) и ждёт появления `token_v2`
   до `auth.login_timeout` секунд.
5. С этим токеном вызываются `POST /api/v3/getSpaces` и
   `POST /api/v3/loadUserContent` — оттуда берутся `user_id`, `space_id`,
   `space_view_id`, имя, e-mail, название и план воркспейса. Это ровно те поля,
   которые вытаскивает `extract_notion_info.js`.
6. Если пар (пользователь, воркспейс) несколько — они выводятся списком, вы
   выбираете одну.
7. Результат пишется в `<проект>/.monoide/auth.json` с правами `600`, окно
   логина закрывается, временный профиль удаляется. Токен на диске виден только
   как хвост (`token_hint`), целиком он в UI не показывается.

Весь прогресс идёт в лог экрана логина через SSE `GET /api/auth/stream?flow=…`.

### 10.2. Firefox и ручной ввод

У Firefox нет CDP-эндпоинта, поэтому для него (и как аварийный путь для любого
браузера) есть блок `PASTE TOKEN_V2 MANUALLY`: логин на notion.so → F12 →
Application/Storage → Cookies → `www.notion.so` → скопировать `token_v2` →
вставить → `ATTACH`. Дальше шаги 5–7 те же.

### 10.3. Связка с notion2api

Если указать путь к папке notion2api:

```json
{ "auth": { "notion2api_dir": "C:/src/notion2api" } }
```

то после входа IDE сама запишет туда `accounts.json` и строку
`NOTION_ACCOUNTS=[…]` в `.env` — вручную вытаскивать токен и перезапускать
сервис не нужно, только рестарт notion2api.

### 10.4. Аккаунт, проверка, выход

Кнопка справа в шапке панели агента показывает имя аккаунта. По клику —
`NOTION ACCOUNT`: поля аккаунта, `CHECK TOKEN` (живой запрос
`loadUserContent`, ловит истёкший токен) и `SIGN OUT` (стирает
`auth.json`, сбрасывает чат и снова запирает агента).

### 10.5. Переменные и отключение

| Что | Зачем |
| --- | --- |
| `MONOIDE_BROWSER_PATH` | явный путь к бинарю браузера, если автопоиск не нашёл |
| `NOTION_URL`, `NOTION_DOMAIN` | если Notion за прокси или на своём домене |
| `auth.login_timeout` | сколько секунд ждать логина (по умолчанию 300) |
| `auth.require_login: false` | снять блокировку, если notion2api уже настроен со своими аккаунтами |

## 11. Windows

### 11.1. Запуск из исходников

```bat
run.bat C:\path\to\project
```

Нужен только Python 3.9+ — зависимостей нет, всё на стандартной библиотеке
(включая свой клиент WebSocket в `ide/ws.py` для DevTools Protocol).

### 11.2. Сборка одного .exe

```powershell
powershell -ExecutionPolicy Bypass -File build_windows.ps1
powershell -ExecutionPolicy Bypass -File build_windows.ps1 -WithPty -NoConsole
```

Скрипт находит Python, делает venv в `.build`, ставит PyInstaller и собирает по
`monoide.spec` (one-file, `web/` внутрь, тяжёлые модули исключены). Результат —
`dist\monoide.exe`:

```bat
dist\monoide.exe C:\path\to\project --base-url http://127.0.0.1:8000/v1
```

### 11.3. Терминал на Windows

| Режим | Когда | Что умеет |
| --- | --- | --- |
| ConPTY (`pywinpty`) | если пакет установлен или собрано с `-WithPty` | полноценный TTY: стрелки, ncurses, цвета |
| Строчный режим | по умолчанию | PowerShell/cmd через pipe, `Ctrl+C` идёт как `CTRL_BREAK_EVENT` |

Оболочку можно задать через `sandbox.shell` в конфиге.
